# URControl

基于 PyQt5 的 UR 机械臂控制、状态显示和数据采集程序，支持 URSim、RealSense 相机及夹爪。

## 配置环境

环境版本以当前 Linux 开发环境为基准：Python 3.10、NumPy 2.2.6、Pinocchio 4.0.0。完整依赖见 [environment.yml](environment.yml)，其中固定了主要直接依赖的版本；底层依赖仍由 Conda 和 pip 解析。

先安装 Miniconda 或 Anaconda，以及 Git。安装过程需要访问 conda-forge、PyPI 和 GitHub。在项目根目录的 Conda 终端中运行；Windows 可使用 Anaconda Prompt：

```bash
python setup_environment.py
conda activate urcontrol
python main.py
```

[setup_environment.py](setup_environment.py) 创建或更新名为 `urcontrol` 的环境，然后在该环境中检查依赖导入及 UR5e 模型加载。已有同名环境中的相关包会按清单调整版本。要单独创建一个环境，可指定名称：

```bash
python setup_environment.py --name urcontrol-new
conda activate urcontrol-new
python main.py
```

脚本安装及检查时禁用用户级包目录，并在环境中设置 `PYTHONNOUSERSITE=1`。这样不会因为本机用户目录恰好装过某个包，就遗漏目标环境的安装。更新已激活的环境后，重新执行 `conda activate urcontrol` 以应用环境变量；使用自定义名称时相应替换。

安装失败时脚本会停止并保留原始错误信息；解决网络或安装错误后可重新运行。脚本按自身位置定位环境清单，启动 `main.py` 时请仍切换到项目根目录。

只检查当前 Python 环境，不安装包：

```bash
conda activate urcontrol
python setup_environment.py --check-only
```

检查会输出实际使用的 Python 和各模块路径，并验证 `rtde`、`rtde_control` 等模块和 Pinocchio 的 MJCF 模型加载。检查过程不连接机器人、不打开相机、不启动窗口。PyCharm 中也应选择同一个 Conda 环境的解释器，并在运行配置中设置 `PYTHONNOUSERSITE=1`。

这份环境清单面向 Linux/Windows 的 64 位桌面环境；本机验证平台为 Linux，Windows 尚未完成整套环境的实际安装验收。图形显示需要系统 OpenGL 支持，RealSense 实物使用还需要对应驱动及设备访问权限。即使只使用 URSim，当前启动导入仍需要相机和夹爪的 Python 依赖。

## `git pull` 后提示缺少 `rtde`

`git pull` 只更新代码，不会同步 Python 环境。项目使用了两套不同的 RTDE 客户端，两者都需要安装：

| 安装来源 / 包名 | Python 导入名称 | 本项目用途 |
|---|---|---|
| [ur-rtde](https://pypi.org/project/ur-rtde/1.6.3/) | `rtde_control`、`rtde_receive`、`rtde_io` | 机器人运动控制、状态接收及 IO |
| [Universal Robots 官方 RTDE 客户端](https://github.com/UniversalRobots/RTDE_Python_Client_Library)（发行包名 `UrRtde`） | `rtde`、`rtde.rtde` | 关节力矩订阅及导纳 RTDE 配方序列化 |

代码整理后，官方 `rtde` 客户端从按需导入改为程序启动时导入。因此，只安装了 `ur_rtde` / `ur-rtde` 的电脑可能在启动时出现：

```text
ModuleNotFoundError: No module named 'rtde'
```

如果原环境其余依赖都已安装，只需在**运行项目的同一个环境**中补装官方客户端：

```bash
conda activate urcontrol
python -m pip install "git+https://github.com/UniversalRobots/RTDE_Python_Client_Library.git@28db033e2cde98f782431452eb810fb76ebad17c"
python -c "from rtde.rtde import RTDE, RTDEException; import rtde_control, rtde_receive, rtde_io; print('两套 RTDE 客户端均可导入')"
```

这里固定本机安装元数据记录的官方源码提交，发行包版本为 `UrRtde 2.8.4`；导纳传输适配器明确要求此版本，不自动尝试其他版本。安装方式见[官方说明](https://github.com/UniversalRobots/RTDE_Python_Client_Library#using-rtde-library)。使用 `python -m pip` 可以明确把包装入该 Python 对应的环境。

若仍报缺包，先确认终端和 IDE 的解释器路径一致：

```bash
python -c "import sys; print(sys.executable)"
python -m pip --version
```

## 依赖名称说明

- Pinocchio 使用 Conda 的 `pinocchio` 包，确保具备项目使用的 MJCF 模型加载能力；[官方安装说明](https://pypi.org/project/pin/4.0.0/)中的 pip 包名为 `pin`。
- OpenCV 使用 `opencv-python-headless`，提供图像处理和视频编码；窗口由 PyQt5 提供。独立环境中不需要再安装 `opencv-python` 或 `opencv-contrib-python`。
- RealSense 使用 `pyrealsense2`；串口与夹爪使用 `pyserial`、`minimalmodbus`。

## 运行

连接真机前，在 `main.py` 顶部配置机器人地址、UDP 地址及端口。使用本机 URSim 时勾选“URSim”，再点击“连接UR”。上电并松抱闸后，RTDE 就绪时启用运动控制按钮。

数据默认保存到 `data/`，采样频率与视频帧率均由 `DATA_COLLECT_FREQ` 配置。关闭窗口时程序等待写盘完成并保存元数据。

夹爪是可选设备。末端未安装夹爪时可直接连接 UR 并使用定点柔顺，无需启动主端。夹爪串口转发不可用时跳过夹爪连接；转发存在但夹爪不响应时，后台仅做低频只读探测，同一故障不重复刷屏。界面显示“未连接 / 无反馈”，不记录默认值或过期夹爪数据；取得有效反馈后恢复正常显示。暂停夹爪时只暂停目标下发，仍读取反馈。

主端离线时 UDP 反馈在后台退避重试，网络异常不退出程序或阻塞界面。机械臂反馈不依赖夹爪，夹爪不可用时三个反馈字段为 `NaN`，详见 [UDP 协议](UR_Utils/UDP_Protocol.md)。无末端负载测试仍使用 UR 端当前的负载与 TCP 配置，程序不根据夹爪通信状态自动改写这些配置。

## 界面与多显示器

新版界面采用布局管理器和可拖动分隔条。左侧切换关节/TCP 控制，以及 UDP、力/力矩、夹爪和运行日志；右侧显示机械臂和两路相机。日志标签会提示未读消息数。底部的限速、采集、停止和下电按钮始终位于固定操作栏。窗口较小时，左侧控制区可以滚动。停止、下电、采集和主要控制按钮使用更大的尺寸和字号；禁用控件使用灰底、灰字和虚线边框。XYZ 点动按钮保留原来的红、绿、蓝颜色，旋转轴使用对应深色；禁用时仅保留轴颜色标记。

窗口初次打开时使用普通窗口，新版以 `.ui` 中的 1360×800 为基准，再适配鼠标所在屏幕，通常占屏幕宽度约七成；不会自动最大化或全屏。字号按屏幕的可用逻辑尺寸适配：4K、200% 缩放时更紧凑，2K、100% 时使用更大的字号。拖到另一台显示器后会重新适配，并保留输入内容和当前标签页；已经手动最大化的窗口保持最大化。右上角“界面大小”可在自动大小基础上选择 90%、110%、125%，选择按显示器和界面模式分别记忆。

“界面 → 经典界面（改版前）”可立即回到原来的布局，“界面 → 新版界面”可切回，程序会记住最后的选择。切换复用同一批业务控件，保留连接、输入值、采集状态和机器人视图，不发送运动命令。经典界面保留原有控件位置和配色，内容随字号等比例缩放；打开、切换屏幕或调整界面大小时，窗口会根据完整内容（包括底部相机）、菜单栏和系统标题栏自动调整尺寸。自动模式优先完整显示，并保留桌面边距；屏幕较小或选择大字导致内容放不下时，通过滚动条查看。新版仍使用较小的默认窗口。

系统 DPI 缩放由 Qt 处理，字号适配使用逻辑尺寸。逻辑像素与物理像素的关系见 [Qt High DPI 说明](https://doc.qt.io/qt-6.8/highdpi.html)。实际跨屏行为取决于桌面环境向 Qt 提供的屏幕信息。

### 当前交付：连续伺服与独立模型生成

当前机器人脚本采用“模型生成 + 唯一运动执行 + 独立遥测发布”结构。模型设计周期为 4 ms，每次准备两个 2 ms 帧目标；唯一执行器负责锚点保持、逐帧 `servoj` 和 `stopj`。稳定等待、偏置采样与正式运行共用连续保持路径。最终位置、速度、加速度和边界制动在目标准备阶段计算，执行器保留实际跟踪、目标有效期、心跳、缩放和停止检查。

每个有限片段携带本轮身份、生成/提交序号、采样和生成时间、适用起止帧，以及依据的已接受命令身份。仅保留当前片段与一个准备片段，通过短临界区整体交接。执行器回报实际采用的序号、帧号及 `q_cmd/qd_cmd`；生成或提交不表示已经执行。片段耗尽、模型计算超预算或执行缺帧时进入停止，不补发过期目标，也不连续补算历史积分。

模型相邻采样起点间隔只作观测，不要求每一次都小于 4.001 ms。实机已复现采样起点的观测间隔达到 5 ms，而该次计算计时为 0 ms、伺服仍连续的情况；旧判断因此误停。模型仍按已承诺两帧的 4 ms 时基推进，计算期限、片段实际交付及连续 2 ms 伺服检查保留，不重复旧运动片段。原因 15 现在仅表示模型计算超预算，其触发样本与原因在同一临界区发布，停止后补发最终计时页。实机证据见 [修复规划第 10 节](URControl_连续伺服修复规划_20261027.md#10-实机模型周期误停修正2026-10-27)。

默认仍为固定关节保持。运行类型、观测轴与预设运动轴在 [admittance_config.py](UR_Utils/admittance_config.py) 分别配置，修改后重启程序：

| 配置 | 含义 |
| --- | --- |
| `DIAGNOSTIC_MODE = "fixed_joint_hold"` | 默认模式；六轴保持启动锚点，外力不驱动目标 |
| `DIAGNOSTIC_MODE = "preset_joint_motion"` | 关闭外力驱动，按预设单轴余弦轨迹微动；默认幅度 0.004 rad、周期 8 s |
| `DIAGNOSTIC_MODE = "admittance"` | 受限单轴质量—阻尼—刚度联调；`JOINT_AXES` 必须只启用 J1 或只启用 J3 |
| `DIAGNOSTIC_AXIS = 1…6` | 观测轴；不再以 0 切换普通模式，也不授权该轴运动 |
| `DIAGNOSTIC_MOTION_AXIS = 1…6` | 仅决定预设微动的运动轴，与观测轴独立 |

预设微动使用专门的命令限速 0.003 rad/s、命令限加速度 0.02 rad/s²、提交前实际跟踪误差上限 0.005 rad。运动轴使用 `DIAGNOSTIC_MOTION_ACTUAL_MAX_QD_RAD_S = 0.003` 和 `DIAGNOSTIC_MOTION_ACTUAL_MARGIN_RAD = 0.001`，其余五轴使用独立的 `DIAGNOSTIC_MOTION_NON_MOTION_ACTUAL_MAX_QD_RAD_S = 0.003` 和 `DIAGNOSTIC_MOTION_NON_MOTION_ACTUAL_MARGIN_RAD = 0.001`，逐帧检查实际速度及位置：运动轴相对锚点为 −0.001～+0.005 rad，其余轴为 ±0.001 rad。后两项从锚点捕获后的启动、偏置到运行生效，越限由唯一执行器停止；不代替绝对关节范围和机器人安全检查。默认轨迹是从锚点增加 0.004 rad 再返回，8 秒单次往返，不是 ±0.004 rad 振荡。

本阶段启动仅开放 `fixed + joint`，即“定点柔顺 + 关节”。遥操作与末端空间仍可离线查看界面，但真实启动入口明确拒绝；其模型预算尚未验证。保持、预设微动及受限单轴导纳均按 `DIAGNOSTIC_DURATION_S` 定时结束，默认 15 s。默认保持和六轴参数草稿不因新增单轴联调而自动改变；切换为 `admittance` 后必须明确只选 J1 或 J3，否则启动边界拒绝。当前实现与本轮现场结果分别记录，实际通过项、失败项和保留边界统一以 [连续伺服修复规划](URControl_连续伺服修复规划_20261027.md) 为准；实现完成不表示真机接触或撤力回位验收通过。

受限单轴使用 `SINGLE_AXIS_*`：最终命令偏移 ±0.004 rad、速度 0.0015 rad/s、加速度 0.02 rad/s²、跟踪误差 0.005 rad；六轴实际速度上限 0.003 rad/s，启用轴实际位置包络 ±0.005 rad，其余轴 ±0.001 rad。固定保持加载取证也检查六轴实际速度 0.003 rad/s 和相对锚点 ±0.001 rad，并在日志声明该契约；不能把未声明此契约的旧保持日志视为已有保护。全部诊断停止确认使用 0.0001 rad/s 的六轴实际速度阈值，且必须确认程序退出。原 M/D/K、死区和固定偏置不变；六轴 `drive` 独立记录，只有启用轴积分。

单轴模型按同一次 4 ms 速度更新分别生成两个 2 ms 期望点，每点独立做速度、加速度和位置制动约束；不再把同一终点重复给两个帧，避免小载荷时首帧到位、次帧归零并丢失模型速度。受限后下一次模型从已承诺的末位移和速度继续推进。

遥测布局为 `telemetry_schema_version=5`，使用五种完整冻结页；日志文件版本仍为 `log_schema_version=3`：

| 页 | 内容 |
| --- | --- |
| `anchor` | 本轮固定锚点、时基、诊断类型、轴选择、输入来源码与遥测版本 |
| `load` | 同一采样的六轴原始输入、输入偏置、滤波量与死区后驱动力，明确输入来源 |
| `execution` | 生成/提交/采用身份、采用帧、有限起止帧、约束原因、执行已采用命令与速度 |
| `timing` | 模型与伺服的实际及最大间隔、目标年龄、分段耗时、六轴偏置标准差和样本数 |
| `statistics` | J1 逐模型周期累计输入统计、配置身份、起止序号和时刻、非零驱动及无效周期数、轨迹与最终完整状态 |

各页带 `run_id`、起止发布序号、模型采样序号和快照时刻。主机只解码身份完整且属于本轮的页，缓存保留每页自己的接收时间；不同页不能拼成同步样本。伺服最大间隔和缺口由执行器持续累计，不因某页未收到而清零。诊断默认订阅 500 Hz RTDE，分析时分别检查原始 RTDE 时间戳和去重后的冻结页身份。

`JOINT_LOAD_SOURCE` 默认仍为 `joint_torque`，使用 `get_joint_torques()` 减去启动期固定关节偏置。第六步新增显式候选 `flange_wrench`：使用法兰点、基座方向表达的 `get_tcp_force()`，按当前零 TCP 偏移的法兰 Jacobian 映射为 `J(q)ᵀ(W−W₀)`；固定的是启动无接触 wrench 均值 `W₀`，其关节投影随当前姿态更新。滤波、死区、M/D/K、运动约束和停止条件共用原路径。该候选只用于当前空法兰小范围末端接触，不能外推为连杆接触检测或携工具后的重力补偿。测力、Jacobian 和映射均计入模型耗时。锚点页用输出整数 43/44 声明来源码（0/1）和布局版本（5），输出整数 45 声明本轮配置身份，主机核对一致后才确认锚点；不会自动换源或重置机器人测力。

全部模式共用上半区输入整数 24～31、输入浮点 24～29、输出整数 24～47 及输出浮点 24～47，输入/输出为独立地址空间。当前输出配方为 22 项标准机器人字段、24 个整数寄存器和 24 个浮点寄存器，完整 RTDE 数据包 904 字节。启动前确认这些地址未被其他程序或 URCap 占用；寄存器明细随日志保存。

初次动态运行要求 `speed_scaling` 和 `target_speed_fraction` 均为 1。空闲时的零缩放不阻止上传；上传后先无运动等待运行状态及双比例首次为 1，主机才发送输入整数 31 的 `scaling_ok=1`。握手确认后任一比例变化都会撤销许可并锁定，执行器进入停止。若伺服间隔先超预算，可先记录原因 16；实际缩放变化事件与最先停止原因均保留，不能只按最终错误码推断因果顺序。

停止覆盖启动、偏置和运行；请求后撤销未采用片段，由唯一运动执行器减速，再确认程序退出和六轴静止。停止未确认时继续保留控制权。减速完成后立即发布本轮结束页，仅保留 6 ms 后退出，避免旧 130 ms 收尾等待侵占软硬心跳保护的间隙；上传前明确要求 NORMAL 安全状态和 RUNNING 机器人模式。新增停止原因如下：

| 代码 | 含义 |
| --- | --- |
| 14 | 目标片段耗尽或模型停止推进 |
| 15 | 模型计算超预算 |
| 16 | 连续伺服出现帧缺口 |
| 17 | 速度缩放发生变化 |
| 18 | 目标交接身份无效 |
| 19 | 受限运动或固定保持的实际速度超限 |
| 20 | 受限运动或固定保持的实际位置超出包络 |
| 21 | 载荷或模型统计存在非有限或无效数值 |

原有原因 1 为请求停止、2 为主机心跳超时、11 为诊断定时结束、13 为启动锚点确认超时。50 Hz 心跳、80 ms 软件超时和 10 Hz 看门狗仍保留。预设微动的正常停止及其通信故障后的外部停止确认，均要求程序退出、六轴实际速度绝对值不大于 `DIAGNOSTIC_MOTION_STOP_MAX_QD_RAD_S = 0.0001` rad/s；不能用普通流程的 0.01 rad/s 阈值确认微动已经静止。现场完整负载保持见第 12 节，无接触微动与低速正常停止见第 13 节，接触响应尚未验收。

控制器进入非 NORMAL 安全状态，或已运行程序进入暂停/暂停过渡时，导纳后端记录 `controller_interrupted` 并终止暂停程序。该故障路径通过独立非阻塞 Dashboard 连接仅发送一次 `stop`，不解保护、不恢复程序；所有连接、发送和回复共用有限期限。正常停止先走原寄存器和唯一 `stopj` 路径；首次停止请求固定 2 秒总期限，重复点击不延长。普通停止在最后 0.5 秒仍未确认时也尝试一次程序终止，超期则保留控制权、交给现有外部静止确认。Dashboard 的 `Stopped` 回复不表示已静止，后续仍须新鲜 RTDE 的程序退出和六轴低速证据。

### 导纳调参与监视

新版和经典主界面的“导纳调参与监视…”打开同一个独立非模态窗口，首次打开不启动运动。窗口可独立移动、最大化和放在另一块屏幕。关闭该窗口只隐藏监视并暂停显示采样，机器人控制、主端提交和原有采集继续运行；重新打开保留草稿和曲线缓存，隐藏期间用断点表示。切换主界面布局、暂停或清空曲线也不改变运动。

窗口保留“遥操作导纳 / 定点柔顺（无主端，撤力回位）”和“关节 / 末端”空间选项；本阶段只允许“定点柔顺 + 关节”启动，其他选择会显示尚未验收的提示并禁用启动。启动后固定场景和空间，停止确认后才能切换。定点模式无需主端在线，即使 UDP 持续到达，也不跟随其目标、不驱动夹爪。

定点模式的启动位置由机器人在确认静止后从实际关节角捕获一次，偏置采样、模型推进和隐藏窗口都不改变锚点。保持模式始终以该构型为目标；预设微动相对该锚点生成轨迹；导纳模式以该锚点为弹簧参考。点击停止、通信故障或安全异常时执行减速停止，不先回锚点；停止后再次启动才捕获新的启动位置。

参数页只保留常规导纳调节的 13 项配置，并随关节 / 末端空间显示对应参数：

- 关节：六轴启用、虚拟惯量 M、阻尼 D、恢复刚度 K、目标力矩、连续死区。
- 末端：柔顺方向、六轴启用、虚拟质量 / 惯量 M、阻尼 D、恢复刚度 K、目标载荷、连续死区。

质量—阻尼—刚度参数用于 `admittance` 模式，固定保持与预设微动不将外力反馈积分为运动。定点启动要求启用轴 M、D、K 均为正，当前空间目标载荷全部为零；不满足时启动入口明确报错，用户需修改并应用草稿。末端参数保留在编辑页与配置中，当前不开放对应启动。载荷滤波、偏移与速度限幅、伺服参数、通信频率、超时、启动条件及寄存器等其余配置仍在 [UR_Utils/admittance_config.py](UR_Utils/admittance_config.py) 中调整，修改后重启程序生效。界面默认值也来自该文件；“恢复默认”仅重置这 13 项的草稿，不改写 Python 文件。

编辑和导入仅修改界面草稿；“应用参数”把 13 项草稿与当前程序加载的 Python 配置合并，校验完整配置，更新下一轮准备值并递增修订号。预设不能覆盖界面之外的配置。存在未应用草稿时不能启动。启动时传入完整准备值副本，后端覆盖控制器的关节范围后返回本轮生效值；差异页仅展示关键参数的草稿、准备值和生效值。启动、偏置采样、运行及停止未确认期间参数锁定。

参数编辑、JSON 文件和采集保留 SI 单位。目标显示可以切换 ° / rad、mm / m；姿态为旋转向量 rx、ry、rz，角度保持连续圈数。`tool_start` 表示启动时固定的工具方向，柔顺中心仍在当前 TCP。两种来源的模型偏移上限均为关节各轴 0.10 rad、末端平移模长 0.03 m、旋转模长 0.15 rad；它们限制相对名义参考的模型偏移，不能替代机器人工作空间及安全限制。

本轮关节死区起点为 `[3, 3, 3, 1, 1, 1]` N·m，关节 K 为 `[30, 30, 20, 5, 5, 3]` N·m/rad，末端平动 K 为 200 N/m、转动 K 为 10 N·m/rad。这些值仍待实际工具和环境整定。持续残余驱动力会形成约 `drive / K` 的平衡偏移；需核对相机及支架的负载、重心、有效 TCP 和偏置，不能只靠增加死区消除嗡鸣或漂移。程序不自动改写机器人安装配置。

1. 按人工联调安排连接本机 URSim 并确认就绪，选择“定点柔顺 + 关节”。

5. 点击“停止导纳”或主界面全局停止，等待停止确认后再调整下一轮参数或导出生效记录。

主端“最新接收”“主机已提交”“机器人已采用”的原有显示保留，当前定点模式标为不适用。模型“生成/提交”与执行器“采用”另外显示，`continuous.execution` 中的 `q_cmd/qd_cmd` 才是带采用身份的命令。顶层 `q_cmd` 仅当前完整执行页有效；其他页不借用旧命令构造同步状态。界面采用目标表可显示最近执行页，并标明页身份；与最新实际反馈相减的数值明确标为“采用/反馈差（异步）”，不是同周期跟踪误差。停止后的执行目标标记为上一轮。

目标及锚点 TCP 通过本地 UR5e 模型及本轮 TCP 偏置计算，明确标为“模型估算”；实际 TCP 来自机器人反馈。未取得本轮 TCP 配置时显示等待状态。模型估算与实际 TCP 的差包含模型和校准差异，不能视为精确控制误差。机器人未上报的候选目标，以及主端未提供的编码器映射和增益，会明确标记缺失，不填零。六轴原始力矩、固定偏置、滤波量与驱动力来自独立载荷页；执行采用速度来自执行页，偏置标准差来自计时页。未取得或偏置未完成的字段保留为空，不拼接不同页制造同步样本。实际关节速度单独使用 `actual_qd`。

数值显示目标 20 Hz、曲线重绘目标 10 Hz，最多缓存 1200 个显示样本，按各自时间戳和计数去重；支持 5 / 15 / 30 / 60 秒窗口、暂停、清空和光标读数。数据过期、隐藏和换轮均产生断点。配置频率与计数估算速率分开显示，主机心跳发送成功不表示机器人已收到，也不将计数进度差称为网络延迟或真实丢包率。

“导出草稿预设”保存 UTF-8 JSON，格式版本 `schema_version` 为 3，使用 `reference_source = teleop | fixed` 及中性参数名，完整保存 13 个界面参数及场景、空间和名称。旧版 v1/v2 因版本与模式语义变化明确拒绝导入，需按原值重新建立 v3 预设，不自动转换历史 `free` 行为。“导出本轮生效记录”使用版本 3（历史版本 2 不改写），保存显式运行类型、模型/执行独立快照及诊断配置，以及完整生效参数、修订号、run_id、开始结束时间、场景空间、TCP/负载、锚点和退出信息，注明 `reference_behavior = moving_reference | fixed_anchor`、`model = fixed_joint_hold | preset_joint_motion | mass_damper_spring`、`backend = urscript`、单位及来源编码。历史文件保持原样。运行记录不能当作调参预设导入；导出不覆盖 Python 配置，也不触发运动。

启停连接交接和停止等待在专用 Qt 工作线程执行，界面继续刷新；所有界面状态、定时器和采集元数据仍由主线程管理。停止请求贯穿排队、交接及偏置采样。停止超时或交接失败后保持控制占用，允许再次显式停止，不自动恢复其他运动。下电、断开、切换 IP 和退出主程序在同一停止确认之后继续。

所有模式共用上述第四版四页遥测布局及寄存器范围，普通导纳不再使用旧四组六轴浮点布局。参考来源编码 1 为 teleop、3 为 fixed、2 仅供识别历史 free 记录；当前启动只允许 fixed，线上源序号为 -1，主端字段标为不适用。参考来源与关节载荷来源是独立字段。

导纳专用通信进程拥有完整的状态有效性、停止、参考和心跳链路，按单调时钟绝对期限调度，停止和到期发送优先；延误后只发最新状态。Qt 和日志写盘留在父进程，停止通过共享事件送达；子进程丢失父进程或桥接租约时请求停止。通信异常时仍须由独立只读状态确认程序退出及静止，才释放控制权。

项目内 `admittance_transport.py` 使用固定 `UrRtde 2.8.4` 的公共序列化接口，运行期 socket 非阻塞；每次至多一次读取和一帧解包。输入组包及发送共用本轮 `ADMITTANCE_RTDE_SEND_TIMEOUT_S` 退出期限，导纳默认配置及 J1 无接触候选均为 10 ms。`ADMITTANCE_RTDE_SEND_WARNING_S` 为 2 ms，超出时逐包记录并累计 `send_warning_count`；超过退出期限仍终止，不重发已写前缀，不续期。两项主机期限独立于机器人 2 ms 伺服及 80 ms 心跳退出，完整本机写出也不表示机器人已收到。Primary 每次至多一次读取和一条消息。预算限制工作量并记录超期，不是 Python 硬实时保证。诊断保存各段墙钟、同线程 CPU、最坏样本的起止时刻、状态锁等待和日志队列，机器人心跳回显与主机最坏发送间隔分别显示。接收同时观察机器人时间推进和持续未排空时间；仅在 socket 不可读且用户缓冲为空时重建窗口。跨时钟推进差只作观测，不能当作单向网络年龄；时间戳停滞或持续未排空超过原 1 s 阈值会请求停止。

通信阈值暂保留 50 Hz 心跳、80 ms 软件超时和 10 Hz 硬看门狗，等待两端间隔实测后协调调整。当前软、硬超时之间约 20 ms，不能保证覆盖最大命令速度 1 rad/s、停止加速度 1 rad/s² 对应的 1 s 减速时间；硬看门狗可能在减速完成前终止程序。实机验收需结合当前速度、允许停止距离和实际间隔确定阈值，不能只放宽软件超时或关闭看门狗。

采集继续由原 `DataCollector` 独立以 20 Hz 执行。完整执行页有效时记录 `ADMITTANCE_Q_NOM`、关节偏移及已采用命令，实际关节角及速度保留其接收身份；定点模式另存 `ADMITTANCE_Q_START`，不创建旧 `ADMITTANCE_FREE_QD / ADMITTANCE_FREE_XD` 组，也不写主端目标组。主机时序组记录收发点统计快照，机器人心跳组记录回显、年龄和最大间隔；稀疏采集不能还原每一次网络时序。每轮元数据使用版本 3、完整参数、诊断选项及来源编码，停止时保存最终时序统计。显示窗口隐藏不影响采集。

### 导纳调试日志

独立导纳窗口中的“记录调试日志”复选框在每次启动软件时默认勾选。开启后，每次启动导纳都会建立一轮调试日志，包括交接、启动失败、偏置采样、运行和停止确认过程。运行期间可随时勾选或取消，不改变机器人运动；隐藏导纳窗口、暂停或清空曲线都不停止日志。该日志独立于 `DataCollector`，无需点击主界面的数据采集按钮。

日志按轮保存在项目根目录的 `logs/admittance/日期时间_run_id/`，窗口显示当前保存路径、写入条数、丢弃条数和错误。新日志使用 `log_schema_version=3`（历史版本 1、2 不改写）。每轮包括：

- `metadata.json`：日志格式与遥测布局版本、实际 Python/系统环境、客户端版本、运行身份、参数与单位、字段说明、RTDE 配方及包长、完整脚本文本、开关历史和结束摘要。
- `records.jsonl`：每行一个 JSON 对象，含 `kind`、记录序号、`run_id`、主机墙钟和单调时间，以及对应数据。RTDE 收发记录另存实际收发点时间，接收状态保留机器人时间戳。

`rtde_state` 按专用 RTDE 连接实际收到的每一帧记录，不依赖窗口的 20 Hz 显示快照。保持、预设微动和当前受限单轴导纳均使用 `DIAGNOSTIC_STATE_HZ = 500`；分析优先读取日志记录的实际协商频率，旧 100 Hz 导纳记录保留原口径。实际收到的频率以时间戳为准，冻结页另按本轮身份、页序号和模型采样序号去重。记录包含实际关节角和速度、TCP 位姿和速度、TCP 力与力矩、关节电流和温度、控制器目标关节角和速度、程序运行状态、机器人模式、安全模式及状态位、速度缩放、控制器执行耗时、TCP 偏移和负载配置，以及本项目使用的全部输出寄存器。派生状态包含 `program_seen`、阶段和退出原因、固定锚点、当前页身份、`load`、`continuous.execution`、`continuous.timing`，以及双端心跳和主机分段耗时。页缓存保留各自身份和时间；当前包的顶层驱动力或命令只有对应完整页有效时才填写。

`rtde_input` 记录每次成功发送的全部输入寄存器，包括启用位、心跳、来源、空间、源序号、锚点确认、本轮身份、缩放许可和参考关节角，同时保留发送耗时与调度诊断。新主端帧单独记录；参数、字段说明、实际上传的完整脚本文本、启动与上传、阶段变化、停止请求、异常、停止确认和日志开关也各有事件。`application_state` 由主界面按目标 10 Hz 补充控制来源、UDP、夹爪、速度滑条和采集状态，各通道带有自己的状态时间，不视为与 RTDE 同时采样。

取消勾选会保留并刷新此前已提交的数据，关闭期间不记录普通数据；重新勾选时在同一轮补充当前参数和状态上下文，并继续写入。本轮生效参数、字段说明、配方与完整脚本在内存中保留，因此中途首次开启也能保存这些固定上下文；样本仅从启用时开始记录，之前的样本不会补录。整轮始终关闭则不创建日志目录。分析时需结合开关事件与跳过计数识别主动停记区间。

导纳通信子进程将冻结消息交给有界队列和单向管道，父进程桥接线程按序提交日志，由专用写入线程完成 JSON 序列化及文件写入，每秒 `flush` 一次。保留子进程的原始收发时刻、桥接序号与来源 PID；正常结束须先交付末尾标记，再排空日志并刷新文件。桥接缺口使用 `process_bridge_gap`，写盘队列缺口使用 `log_gap`，队列满时均不等待磁盘；子进程异常退出而没有末尾标记时不能声称日志完整。诊断另存写盘分段、队列高水位和排队年龄。创建目录、序列化或写盘失败会明确显示在界面并停止本轮日志记录；机器人控制与停止确认继续由原流程处理。

原始数据中的非有限浮点数使用 `{"non_finite_float":"NaN"}`、`Infinity` 或 `-Infinity` 标记，保留异常值身份并保持标准 JSON，不替换成零。日志不会自动删除，目录已加入 Git 忽略规则。

日志中的 `actual_TCP_force` 是 RTDE 上报的 TCP 力与力矩，`actual_current` 是关节电流，二者不能当作脚本 `get_joint_torques()` 的补偿关节力矩。`drive` 是经过启动基线扣除、滤波、目标载荷扣除和连续死区处理后的有效载荷。第四版载荷页记录 `load_source` 和六轴 `input_raw_nm/bias_nm/filtered_nm/drive`；历史第三版的 `tau_raw_nm` 始终按 `joint_torque` 解释，分析器按元数据显式区分，不改写旧日志。执行页记录已采用 `q_cmd/qd_cmd/q_nom/delta_q`；偏置未完成的量为空，未上报的候选目标或内部量不填零。控制器 `target_q/target_qd` 与执行已采用 `q_cmd/qd_cmd` 分别记录；前者用于原始 500 Hz 动态窗口分析，后者保留执行页采样边界。`program_seen` 为假时，输出寄存器可能仍属于此前程序，不能当作本轮有效导纳状态。

机器人标准字段的类型和单位依据 [UR 官方 RTDE 字段文档](https://docs.universal-robots.com/tutorials/communication-protocol-tutorials/rtde-guide.html#robot-controller-outputs)，本轮字段说明与寄存器映射随日志保存。

### 历史：2026-10-26 URSim 人工联调

以下结果属于连续伺服修复前的实现；所涉及遥操作和末端空间当前不开放启动，新版现场结果以 [连续伺服修复规划第 8～14 节](URControl_连续伺服修复规划_20261027.md) 为准。
